# 역할 분담

## 1. 분담 기준

현재 PRD의 핵심 흐름을 기준으로 기능 영역을 나눈다.

`회원가입/로그인 → 블로그 생성 → 글 작성/발행 → 피드 노출 → 글 상세 조회`

API의 요청·응답 형식, 인증 방식, 상태값, 검증 규칙은 `instruction/API.md`를 기준으로 한다. 이 문서에서는 API 명세를 반복하지 않고 각 개발자의 담당 범위와 협업 범위만 정의한다.

- 개발자 A, B, C가 각각 하나의 주 담당 영역을 가진다.
- 주 담당자는 해당 영역의 구현과 검증을 책임진다.
- 데이터 모델이나 공통 규칙을 변경할 때는 관련 담당자와 먼저 합의한다.
- 모든 변경 사항은 작은 단위로 나누어 리뷰 후 통합한다.
- 담당 영역과 관계없이 최종 품질 검증에는 전원이 참여한다.

## 2. 역할 요약

| 역할 | 주 담당 범위 | 협업 범위 |
|---|---|---|
| 개발자 A | 사용자, 인증, 블로그 | 데이터 구조, 접근 권한, 사용자 흐름 |
| 개발자 B | 글, 피드, 검색 | 발행 상태, 조회 흐름, 목록 처리 |
| 개발자 C | 테스트, 품질, 문서 | 예외 상황, 회귀 검증, 릴리즈 점검 |

## 3. 개발자 A: 사용자·인증·블로그

### 담당 범위

- 회원가입, 로그인, 로그아웃 관련 사용자 흐름
- 로그인 사용자 정보와 인증 상태 관리
- 블로그 생성 및 블로그 기본 정보 관리
- 블로그 주소 중복 및 형식 검증
- 사용자와 블로그 사이의 소유 관계
- 인증이 필요한 기능의 접근 권한
- 사용자·블로그 영역의 예외 상황과 데이터 무결성

### 담당하지 않는 범위

- 글 작성, 수정, 삭제 및 발행 흐름
- 통합 피드, 검색, 정렬, 페이지네이션
- 공통 테스트 체계와 최종 릴리즈 검증

### 협업 지점

- 개발자 B와 글 작성자의 블로그 소유권 및 접근 범위를 합의한다.
- 개발자 C에게 사용자·블로그 영역의 정상/실패 검증 기준을 전달한다.
- 공통 데이터 구조 변경은 개발자 B와 함께 검토한다.

## 4. 개발자 B: 글·피드·검색

### 담당 범위

- 글 작성 및 임시저장 흐름
- 글 공개 발행, 수정, 삭제 흐름
- 글 상세 조회와 조회수 처리
- 블로그별 공개 글 목록
- 전체 공개 글 피드
- 제목·본문·블로그명 검색
- 최신순·인기순 정렬
- 목록 페이지네이션
- 공개 글과 임시저장 글의 노출 범위

### 담당하지 않는 범위

- 회원가입, 로그인, 로그아웃
- 블로그 소유권 및 사용자 인증 자체
- 전체 테스트 기준과 릴리즈 승인

### 협업 지점

- 개발자 A와 글 작성자 확인 및 블로그 접근 권한을 합의한다.
- 개발자 C에게 글 상태별 노출 조건과 핵심 검증 시나리오를 전달한다.
- 피드에 노출되는 데이터의 기준은 PRD와 `instruction/API.md`를 함께 따른다.

## 5. 개발자 C: 품질·테스트·문서

### 담당 범위

- PRD 핵심 사용자 흐름을 기준으로 한 테스트 시나리오 작성
- 사용자·인증·블로그 영역의 정상/실패 검증
- 글·피드·검색 영역의 정상/실패 검증
- 빈 데이터, 잘못된 입력, 권한 오류, 중복 요청 검증
- 재현 가능한 버그 리포트 작성
- 수정된 버그의 재검증과 회귀 테스트
- 프로젝트 실행 방법과 기능 문서 보완
- 최종 Definition of Done 점검

### 담당하지 않는 범위

- 사용자·인증·블로그 기능의 주 구현
- 글·피드·검색 기능의 주 구현
- 담당자와 합의하지 않은 데이터 구조 변경

### 협업 지점

- 개발자 A에게 사용자·인증·블로그 검증 결과를 전달한다.
- 개발자 B에게 글·피드·검색 검증 결과를 전달한다.
- 버그는 재현 절차, 기대 결과, 실제 결과, 영향 범위를 포함해 기록한다.

## 6. 기능별 주 담당

| 기능 | 주 담당 | 협업/검증 |
|---|---|---|
| 회원가입·로그인·로그아웃 | 개발자 A | 개발자 C 검증 |
| 사용자 정보·인증 상태 | 개발자 A | 개발자 C 검증 |
| 블로그 생성·조회 | 개발자 A | 개발자 B 연계, 개발자 C 검증 |
| 블로그 소유권·접근 권한 | 개발자 A | 개발자 B 협의, 개발자 C 검증 |
| 글 작성·임시저장 | 개발자 B | 개발자 A 권한 협의, 개발자 C 검증 |
| 글 발행·수정·삭제 | 개발자 B | 개발자 A 권한 협의, 개발자 C 검증 |
| 글 상세·조회수 | 개발자 B | 개발자 C 검증 |
| 공개 피드·검색·정렬 | 개발자 B | 개발자 C 검증 |
| 예외·경계값 검증 | 개발자 C | 각 기능 담당자 수정 |
| 회귀 테스트·릴리즈 점검 | 개발자 C | 전원 참여 |
| 실행 방법·기능 문서 | 개발자 C | 전원 내용 확인 |

## 7. 협업 규칙

- API 세부사항은 역할 문서가 아니라 `instruction/API.md`를 기준으로 확인한다.
- 담당 영역의 변경은 주 담당자가 먼저 정리하고 관련 담당자에게 공유한다.
- 공통 데이터 구조, 인증/권한, 글 공개 상태에 영향을 주는 변경은 구현 전에 합의한다.
- PR에는 변경 범위, 검증 방법, 남은 문제를 작성한다.
- 개발자 C가 발견한 문제는 담당 개발자가 수정하고, 개발자 C가 수정 결과를 재검증한다.
- 최종 제출 전 PRD의 완료 기준을 전원이 함께 확인한다.
